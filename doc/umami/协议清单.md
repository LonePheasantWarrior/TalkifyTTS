# Umami 部署与协议清单

本文件是 Talkify 客户端与自建 Umami 实例之间的**部署契约**。客户端版本、服务端镜像、脚本与响应语义变化时，先更新本文件并跑契约回归，再发布客户端。

> 未填写的项必须在部署时补齐；"未知"不等于默认安全。客户端只能保证自己的发送边界，服务端过滤、限流、存储与保留策略需由运维确认。

## 3. 客户端使用的端点

| 端点 | 方法 | 当前状态 | 说明 |
|------|------|---------|------|
| `/api/send` | POST | 启用 | pageview / 自定义事件 / identify；有界队列 + 单 worker 顺序发送 |
| `/api/websites/{id}/recorder` | GET | **停用** | 界面诊断能力整体关闭，当前不请求 |
| `/api/record` | POST | **停用** | 当前不产生任何流量 |

配置要求：

- `umami.endpoint`：合法 HTTPS URL，host 非空、无非法百分号转义、无凭据/query/fragment，允许子路径，不带尾斜杠。
- `umami.websiteId`：网站 UUID。
- debug 构建只读取 `umami.debugEndpoint` / `umami.debugWebsiteId`（或 `UMAMI_DEBUG_*`），未配置则不发送，绝不回退生产配置。
- 构建脚本与运行时使用等价的严格校验；部分配置或非法值直接使构建失败。发布可通过 `-PtelemetryRequired=true` / `TALKIFY_REQUIRE_TELEMETRY=true` 强制要求配置存在。
- `:app:verifyTelemetryConfigMatrix` 验证构建侧校验矩阵；`:app:writeTelemetryStatus` 生成规范化状态，发布工作流据此生成 Step Summary/Release 说明。

## 4. 请求与响应契约

### 4.1 基础发送

请求头：

- `User-Agent: Talkify/<versionName> (Linux; Android <osVersion>; <model>)`
- `x-umami-website-id`
- `x-umami-hostname`
- `x-umami-cache`（仅令牌存在时）

响应分类（客户端实现于 `UmamiClient`）：

| 响应 | 客户端处置 | 诊断计数 |
|------|-----------|---------|
| 2xx + JSON 且 `cache` 为非空字符串 | 按序更新会话令牌 | 成功 |
| 2xx + `{beep:"boop"}` | 视为机器人过滤，不重试、不更新令牌 | 服务端过滤 |
| 2xx + `{ok:false, reason}` | 明确拒绝；reason 含 disabled 时覆盖全部通道 | 拒绝 / 远端停用 |
| 2xx + `disabled:true` | 停用基础与录制通道，清空队列 | 远端停用 |
| 2xx 但空体/HTML/畸形 JSON/字段类型错误/超过 16KiB | **协议错误**：不更新令牌、不增加成功、不重试 | 协议错误 |
| 400 + 未携带令牌 | 按配置/请求拒绝处理，不重试 | 拒绝 |
| 400 + 携带令牌 + 明确 token/cache/session 失效 | 清除缓存后受控重建一次 | 无效令牌 |
| 400 + 其他原因（schema/站点不存在等） | 按拒绝处理，不重试（换令牌无法修复） | 拒绝 |
| 429 | 完整遵守 `Retry-After`（秒数或 HTTP-date，不截短）；站点级闸门约束后续事件；等待超过事件 TTL 则丢弃。即使本次已是最后一次尝试（重试预算耗尽），仍先按该响应更新站点冷却 | HTTP 错误 / TTL / 发送失败 |
| 5xx / 临时网络错误 | 优先遵守 `Retry-After`，否则指数退避 + 抖动；最多重试 2 次；重试耗尽时最后一次响应携带的 `Retry-After` 仍约束后续事件 | HTTP 错误 / 发送失败 |
| 其他 4xx | 不重试 | HTTP 错误 |

成功响应契约需在部署实例上确认：本客户端**只**把带非空 `cache` 的 2xx JSON 视为成功。若实际部署的成功响应不含该字段，必须先更新本清单并同步修改客户端，不能靠“空响应也算成功”掩盖代理错误。

### 4.2 录制（当前停用，恢复前必须联调）

- 请求头必须与基础通道一致携带应用 UA；不得用伪造浏览器 UA 绕过机器人防护，也不得全局关闭服务端防护。
- 过滤/拒绝/停用响应必须被识别并计入本地诊断；HTTP 200 不代表入库。
- 单个 record 包最终 UTF-8 包体 ≤500KB；单事件超限走 `umami:rrweb-event-fragment` 分片（200KB UTF-8 预算）。
- 恢复前需在部署实例上验证：FullSnapshot 单独成包、增量批处理、分片重组、跨场次排序、热图背景与坐标。

## 5. 服务端配置与本地硬上限

| 项 | 服务端值 | 客户端硬上限 |
|----|---------|-------------|
| `enabled` | 待填写 | 必须为 true 才可能录制 |
| `replayEnabled` / `heatmapEnabled` | 待填写 | 当前客户端总开关关闭 |
| `sampleRate` / `heatmapSampleRate` | 待填写 | 规范到 0..1 |
| `maxDuration` | 待填写 | 10s..300s；配置低于 10s 时拒绝录制（服务端只能收紧，不能把短时长抬高） |
| `maskLevel` | 待填写 | 支持 `strict`（全量遮罩）；未知值不做承诺 |
| `blockSelector` | 建议留空 | 非空时**拒绝录制**（网页 CSS selector 无法映射原生） |
| 请求体上限 | 待填写 | `/api/send` 单事件 data 按 UTF-8 JSON 实际字节 ≤4KiB；响应读取 ≤16KiB；record 包 ≤500KB |
| 采样/保留 | 待填写 | 基础队列 60s TTL（单调时钟）；崩溃摘要本地保留 7 天、入选队列后才删除 |
| 窗口汇总 | 待填写 | 5 分钟主动到期或第 500 次立即发送；不需要后续请求/Activity 触发 |

服务端采样率、`maxDuration`、响应体大小等只能进一步收紧本地许可，不能开启用户未选择的能力。

## 6. 客户端数据契约（发送前硬校验）

- 每个事件在 `TelemetrySchema.EVENT_SPECS` 声明允许键、必填键、类型、枚举与数值范围；未知属性直接拒绝，不存在“键名合法即可携带”的通道。
- 可能包含用户内容的字段一律是有限枚举或结构化签名；普通字符串拒绝 URL/换行/控制字符。崩溃帧必须匹配类/方法/行号格式，帧数量与链深度必须自洽。
- 组装公共属性后按 UTF-8 JSON 实际字节数限制 4KiB；转义字符和中文都计入。队列预算使用同一字节数。
- 异步生产者携带创建时的许可代际；关闭/重开后的旧数据不会进入新会话。

## 7. 运维与隐私

- 服务端应配置限流、配额、事件字段校验与管理面权限；记录代理/服务端 IP 日志的处理方式与实际保留周期。
- 数据保留与删除方式：待填写。
- 客户端不采集 IMEI/MAC/Advertising ID，也不引入跨安装持久 ID；但 Umami 会基于 IP + User-Agent 派生匿名会话，IP 可能反映大致地区，不能宣称整条链路"绝不接触 IP"或"完全无法识别"。
- 仓库与 Release 中不得出现管理 token；`websiteId` 不是认证凭据。

## 8. 升级前契约回归

1. 在独立测试站点完成「发送 → 数据存储 → 报表计算 → 展示」全链路验证，测试数据不得进入生产站点。
2. 同一会话分别发送基础事件、record、heatmap（录制恢复后），确认三者到达预期会话。
3. 模拟 200/正常 cache、200/空体/HTML/畸形 JSON、200/过滤、200/disabled、400 无令牌、400 schema、400 明确令牌失效、429（120 秒与 HTTP-date）、500，确认客户端分类准确且无重试风暴/提前重试。
4. 校验事件属性：无 URL、代理地址、API Key、朗读文本、原始自定义模型/音色 ID；未知属性被拒绝；单事件 UTF-8 data 不超过 4KiB。
5. 验证 5 分钟窗口在没有后续请求时仍发送、恰好 500 次立即发送；关闭许可后定时任务取消，旧 record/flush 恢复时不删除新代际窗口、旧窗口不发送。
6. 验证崩溃摘要循环 cause/超大栈有限结束，空栈深链的 cause 读取次数受深度预算约束；后台服务独立启动也尝试补报；未配置/队列满/schema 拒绝时不删除摘要，过期后清理。
7. 记录本次部署镜像 digest、脚本 SHA256、Umami commit 与验证日期到本文件。
8. 迁移日期、App 版本、schema 版本与指标口径变化写入报表注释；新旧浏览量/成功率不得直接拼接成连续趋势。
